# Polynomial vs Linear Regression

A hands-on notebook that builds a synthetic non-linear dataset and compares **Linear Regression** against **Polynomial Regression** at different degrees — showing underfitting, a good fit, and overfitting side by side.

---

## What this script does

1. Generates a synthetic dataset where `y` depends on `x` **quadratically**, with random noise added.
2. Fits a **plain Linear Regression** model on it and visualizes how badly a straight line fits curved data.
3. Fits a **Polynomial Regression (degree = 2)** model and shows how it matches the true curve.
4. Fits a **Polynomial Regression (degree = 20)** on a smaller sample and shows the model going wild — classic overfitting.
5. Puts all three (Linear, Good-degree Polynomial, Bad-degree Polynomial) in one figure for direct comparison.

---

## Dataset

- `x` is drawn uniformly between **-3 and 3**, 200 points.
- `y` follows the quadratic relationship `0.5x² + x + 2`, plus Gaussian noise (mean 0, standard deviation 1) so points scatter realistically around the curve instead of sitting exactly on it.
- A fixed random seed makes the dataset reproducible — running the script again gives identical results.

For the overfitting demo later in the script, a **smaller dataset** (30 points, more noise — standard deviation 1.5) is used deliberately — fewer points make it much easier for a high-degree polynomial to "memorize" noise instead of learning the real pattern.

## Step-by-step breakdown

### 1. Imports
Brings in the core libraries used throughout: data handling (`pandas`, `numpy`), plotting (`matplotlib`), and modeling tools from `scikit-learn` — `LinearRegression`, `PolynomialFeatures`, `r2_score`, and helpers like `Pipeline`, `StandardScaler`, and `train_test_split` (available for extension, though not all are used in the core comparison).

### 2. Sorting `x`
Matplotlib draws lines by connecting points **in array order**. If `x` isn't sorted before plotting a fitted line, the line zigzags back and forth instead of forming a smooth curve. Sorting `x` (and applying the same order to any values plotted against it) fixes this.

### 3. Linear Regression
A straight line is fit through clearly curved data — this is the **underfitting baseline**.

The R² score comes out to roughly **0.51**, meaning the line explains only about half the variance in `y`. The rest is the curvature it can't capture.

### 4. Polynomial Regression (degree = 2)
Expanding each `x` into `[1, x, x²]` and then fitting a linear model on that expanded feature set corresponds to fitting a smooth parabola in the original `x`-`y` space. This matches the true underlying pattern almost exactly, since the data was generated from a quadratic function.

**Important detail:** predictions used for plotting are generated by transforming the sorted `x` values through the *same already-fitted* transformer (not re-fitting it) — this keeps the fitted model consistent while producing a smooth, correctly-ordered line.

### 5. Overfitting demo (degree = 20, fewer points)
A fresh, smaller (30-point), noisier dataset is used, and predictions are made on 300 evenly spaced points across the same range rather than only the original training points. This is what reveals overfitting properly: a high-degree curve can look deceptively smooth if you only ever evaluate it *at* the training points, but sampling densely in between exposes the wild oscillations.

Three models are fit and plotted side by side:
| Panel | Model | Degree | Behavior |
|---|---|---|---|
| 1 | Linear Regression | — | Underfits — straight line ignores the curve |
| 2 | Polynomial Regression | 2 | Good fit — smooth curve tracks the true pattern |
| 3 | Polynomial Regression | 20 | Overfits — wild spikes, chases noise instead of signal |

## Why polynomial degree causes underfitting *and* overfitting

Polynomial degree controls **model flexibility** — how many "bends" the curve is allowed to have. Both failure modes come from picking degree wrong relative to the true complexity of the data, just in opposite directions.

### Underfitting (degree too low)

- A degree-1 "polynomial" is just a straight line — it has only 2 parameters (slope, intercept) and can only represent one shape: a line.
- The real data here follows `0.5x² + x + 2`, a curve. No straight line can bend to match a parabola.
- Result: **high bias** — the model's assumptions are too simple for the true relationship, so it systematically misses the pattern everywhere, not just at a few points. Both training and test error stay high, and adding more data won't fix it, because the model *structurally cannot* represent a curve.
- In the notebook this shows up as the red line cutting straight through the U-shaped data, ignoring the dip in the middle.

### Overfitting (degree too high)

- A degree-20 polynomial has 20+ tunable coefficients. With only 30 training points, the model has more than enough freedom to pass extremely close to *every single point*, including the random noise on each one.
- Instead of learning the smooth underlying rule (`0.5x² + x`), it starts treating each noisy fluctuation as if it were meaningful signal.
- Result: **high variance** — the fitted curve becomes extremely sensitive to the exact training points. Between training points, the curve has to swing wildly to loop back and hit the next noisy point exactly, producing the huge oscillations and spikes seen in the degree-20 panel.
- It fits the training data almost perfectly (r² near 1.0 on training data) but performs poorly on new, unseen `x` values, because it learned noise, not the true pattern.

### The right degree (degree = 2, in this case)

- Since the data-generating function is genuinely quadratic (`0.5x² + x + 2`), a degree-2 polynomial has exactly the right amount of flexibility: enough to bend into a parabola, not so much that it can wiggle through noise.
- This is the **bias-variance sweet spot** — low bias (correct shape) and low variance (doesn't overreact to noise).

### General rule of thumb

| Degree vs. true complexity | Bias | Variance | Result |
|---|---|---|---|
| Too low | High | Low | Underfitting |
| Just right | Low | Low | Good generalization |
| Too high | Low | High | Overfitting |

In practice (outside toy examples like this one), the right degree isn't known in advance — it's chosen using techniques like **train/test split**, **cross-validation**, or **regularization** (e.g. Ridge/Lasso) rather than by visually inspecting the plot, since real data doesn't come with a known formula to check against.
